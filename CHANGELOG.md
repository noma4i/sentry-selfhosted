# Changelog

Notable changes to this deployment, relative to the upstream
`getsentry/self-hosted` compose stack.

## 2026-10-03

### Changed

- `kafka` and `clickhouse` healthcheck interval raised to 30s with 10 retries
  (via `docker-compose.override.yml`). Every check is a `docker exec`, and on a
  host running dozens of containers the per-check overhead adds constant
  baseline CPU for no extra safety.

## 2026-07-26

### Security

- Deployment-specific values are no longer kept in tracked files. `.env` (which
  is generated by an external secret sync) and `sentry-conf/config.yml` (which
  holds GitHub App credentials, including a private key) are now untracked and
  ignored; `.env.example` and `sentry-conf/config.yml.example` document the
  required keys with placeholders instead.
- The public hostname, mail domain and DKIM selector are read from the
  environment (`SENTRY_PUBLIC_URL`, `SENTRY_MAIL_HOST`, `SENTRY_MAIL_HOSTNAME`,
  `SENTRY_DKIM_SELECTOR`) rather than hardcoded in `docker-compose.yml` and
  `sentry-conf/sentry.conf.py`. `SENTRY_PUBLIC_URL` is passed to the Sentry
  containers and applied only when set, so an unset value falls back to
  upstream behaviour.

### Fixed

- `snuba-api` healthcheck no longer hangs. The upstream check opens a raw
  `/dev/tcp` socket and pipes it into `grep ok -s -m 1`; under the granian WSGI
  server the connection is kept alive, so `grep` never reaches EOF and the
  check runs until its 30s timeout on every attempt. The container was
  therefore reported `unhealthy` indefinitely (observed failing streak: 175)
  even though `/health` answered correctly, and each timed-out attempt leaked a
  zombie `grep` because the `snuba-api` PID 1 does not reap children (163 had
  accumulated). Replaced with a `curl` probe against the same endpoint via
  `docker-compose.override.yml`, which returns immediately.

### Changed

- SMTP container switched from `registry.gitlab.com/egos-tech/smtp` to
  `boky/postfix`, with DKIM signing enabled and keys supplied through an
  external volume instead of being autogenerated.
- Memory limits raised for the workloads that were hitting their ceiling:
  `clickhouse` 2g -> 4g, `web` 1g -> 2g.
- uWSGI `reload-on-rss` raised 400 -> 900 to stop the web worker recycling
  itself mid-request under normal load.

### Added

- Feature flags enabling multi-organization SCM integrations
  (`integrations-scm-multi-org`, `organizations:integrations-scm-multi-org`,
  `organizations:github-multi-org-upsell-modal`). The self-hosted UI otherwise
  renders the legacy single-org installation button and offers no way to attach
  a GitHub App to more than one organization.
